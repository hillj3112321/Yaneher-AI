# Янехер Чат / YaneCLIBB v10

Рабочая модернизация **существующего YaneCLIBB v9**, а не новый сайт с пустой базой: сохранены калькулятор, трекер цели 500 000 просмотров, диагностика, разбор файлов, ссылки Twitch/Telegram и совместимость с локальными записями v7–v9.

## Быстрый запуск без сервера

Откройте `YaneherChat_v10_offline.html` из корня скачанных файлов в браузере. В этой версии работает: навигация, мобильный дизайн, темы, базовые переключатели языка, уроки, диагностика, калькулятор, трекер 500К, CSV-экспорт, локальный ЯнеИИ-справочник, загрузка фото/видео и **визуальная выборка по всему таймлайну** с таймкодами. Настоящий ИИ, общий чат и админ-синхронизация не подключены до настройки сервера.

Данные трекера находятся **только в `localStorage` конкретного браузера и адреса сайта**. При переносе со старого домена на новый браузер не переносит их автоматически. Перед сменой адреса экспортируйте CSV; автоматического импорта CSV в этой версии пока нет. Очищение хранилища браузера удалит локальные записи.

## Публикация на Netlify

1. Загрузите папку проекта в приватный GitHub-репозиторий или другой репозиторий, поддерживаемый Netlify. В корне должен лежать `netlify.toml`.
2. Создайте сайт Netlify из этого репозитория. Директория публикации — **`site`**, функции — **`netlify/functions`**. Команда сборки не нужна.
3. `site/config.js` содержит только **публичные** настройки Supabase и URL видеосервера. Не вставляйте в него никакие секретные ключи.
4. Сайт работает и без настроенных API. Пока ключи не заданы, ИИ обозначен как локальный справочник, общий чат — как не подключённый.

> Простая статическая загрузка файла `index.html` без остальных папок не подключит серверные функции, CSS и JS. Для автономного просмотра используйте отдельный HTML-файл.

## Настоящий ЯнеИИ — подключение API

В **Netlify → Environment variables** добавьте (доступ к Functions):

- `OPENAI_API_KEY`: секретный API-ключ провайдера (только сервер).
- `OPENAI_MODEL`: модель с поддержкой изображений; по умолчанию `gpt-4.1-mini` (проверьте доступность для вашего аккаунта).
- `YANE_AI_ACCESS_CODE`: длинный код для пользователей, которым разрешены платные обращения к ИИ. **Не равен API-ключу!**

После нового деплоя откройте вкладку ЯнеИИ: статус меняется на `API READY`. При первом вопросе приложение запросит код доступа. Он хранится только в `sessionStorage` вкладки, не в исходном HTML.

**Ограничения и защита:** общий код — базовая защита, а не полноценное управление платным доступом. Для публичного сайта настройте отдельную авторизацию, серверные лимиты по пользователям/IP, капчу, месячный бюджет и мониторинг затрат. В этой версии функция ограничивает размер текста и кадров, проверяет origin, не ведёт собственной истории сообщений и не сохраняет изображения. Но отправленные кадры и вопросы поступают провайдеру модели по API. При загрузке видео в ЯнеИИ в API отправляются **выбранные кадры по разным частям ролика**, а не исходный файл и не аудио. Нельзя обещать понимание всей динамики и музыки по кадрам.

## Общий чат, список нарезчиков, правила, баннер, лучшие видео и админка

Для реальных общих данных используйте **Supabase**:

1. Создайте проект Supabase и выполните `db/supabase.sql` в **SQL Editor**.
2. В `site/config.js` внесите `supabaseUrl` и **публичный** `supabaseAnonKey` (не `service_role`).
3. Настройте в Supabase Authentication: email OTP / magic link, адрес сайта и допустимые redirect URL. Для отправки писем настройте SMTP и лимиты поставщика.
4. Войдите по email через раздел **Общий чат**. Найдите UUID своей учётной записи в **Authentication → Users**.
5. Назначьте администратора **из SQL Editor**:

```sql
update public.profiles set role='admin' where id='<UUID из Authentication → Users>';
```

6. Перезайдите и откройте **Управление**. Теперь можно добавить настоящих участников и их статусы, изменить лимит мест, опубликовать **подтверждённые** правила, загрузить баннер (с разрешением), добавить настоящие видео с автором и оригинальной ссылкой, скрывать жалобы.
7. Участники, правила, подборки и сообщения станут общими для всех посетителей сайта. Для чата в SQL предусмотрены RLS, 5-секундный промежуток между сообщениями одного автора и кнопки жалоб. Публичный чат всё равно требует активной модерации и защиты от злоупотреблений.

**Важно:** никакие «официальные правила Янехера», реальные никнеймы и подборки 20–30 видео автоматически не придумываются. Пока администратор не предоставил подтверждённые материалы, разделы показывают честные пустые состояния. Видео из Twitch не всегда можно встроить, поэтому кнопка оригинала остаётся главным способом просмотра. «Скачать» появляется только для прямых MP4 при отметке разрешения автора.

## Расширенный анализ всего видео + уровни звука

При необходимости разверните отдельно **`video-worker`** (Docker, сервер с FFmpeg; Netlify Functions для такого анализа не подходят):

```bash
cd video-worker
docker build -t yane-video-worker .
docker run --rm -p 8080:8080 \
  -e VIDEO_WORKER_CODE='ваш_секретный_код' \
  -e ALLOWED_ORIGINS='https://your-site.netlify.app' \
  yane-video-worker
```

Размещайте worker за HTTPS (например, на хостинге контейнеров). В `site/config.js` укажите `videoWorkerUrl: 'https://ваш-видеосервер.example'`. В интерфейсе появится кнопка **«Серверный анализ всего файла»**. Пользователь вводит отдельный код доступа.

Worker действительно запускает FFmpeg/FFprobe над файлом и делает следующее:

- Считывает разрешение, длительность, FPS, кодек и наличие аудиодорожки.
- Проходит видеоряд по кадрам для поиска **вероятных** сценовых переходов по визуальному порогу.
- Делает до 120 равномерных визуальных выборок по всему видео, отмечает тёмные/пересвеченные и почти статичные участки.
- Анализирует аудиосигнал фильтром `silencedetect` и приблизительную интегральную громкость `ebur128` (LUFS).
- Возвращает таймкоды, метаданные и изображения для подробного отчёта на сайте.
- Хранит исходный файл **временным** образом на сервере и удаляет после запроса; постоянного видеохранилища нет.

Лимиты рабочего примера: **150 МБ**, до **600 секунд**. Процесс может занимать существенное время и вычислительные ресурсы. Необходимо защищать worker авторизацией, лимитами запросов и тарифными квотами. Его нельзя запускать в большом публичном масштабе без этих мер.

При наличии обеих интеграций (worker + ИИ) можно попросить ЯнеИИ разобрать метаданные и **выбранные кадры разных сцен**, получив рекомендации с таймкодами. **Ни визуальная выборка в браузере, ни worker не позволяют безусловно оценить смысл речи, юмор, контекст, авторские права или реальное удержание аудитории.** Для понимания звукового содержания потребуется отдельная транскрипция/мультимодальный сервис, а для удержания — реальные данные TikTok/YouTube.

## Языки и темы

Сайт поддерживает RU / UA / EN и переключение тёмной/светлой темы без перезагрузки. Выбор хранится в браузере. Переведены основные названия вкладок, формы, кнопки и статические пояснения. **Полное покрытие динамических диагностических текстов и отдельных учебных материалов перевода пока не имеет**; они остаются на русском, чтобы не искажать смысл. Это известная незавершённая часть, а не заявка на полностью трёхъязычный контент.

## Что реализовано и что ещё нужно

**Проверено локально:** открытие сайта без JS-ошибок, переключение вкладок, мобильный размер 390px без горизонтального скролла, сохранение **двух разных записей на одну дату**, обновление просмотров без дублирования, язык/тема, фильтры обучения, локальный ответ ЯнеИИ и обработка тестового MP4 с таймкодами. Worker проверен на тестовом MP4 с FFprobe, сканированием кадров и звукового метаданных.

**Остаётся настроить или доделать:** секретный ключ и модель для генеративных ответов; отдельный контейнер для серверного видеоанализа; Supabase/Auth и реальные участники, тексты правил, баннеры, подборки; полноценная локализация динамического контента; обработка речи/распознавание текста видео; надёжные квоты, мониторинг расходов, автоматизированные нагрузочные тесты и публичная модерация; импорт CSV и синхронизация личного трекера между устройствами. Все такие функции не замаскированы под работающие.

## Где исходники

```text
site/index.html                   основной HTML
site/assets/app.js               существующая логика v9 + улучшения v10
site/assets/upgrade.css          дополнительные стили и светлая тема
site/config.js                   публичные настройки
netlify/functions/yaneai.mjs     защищённый серверный вызов ИИ
db/supabase.sql                  таблицы, политики доступа, триггеры
video-worker/                    отдельный сервер FFmpeg
netlify.toml                     конфигурация Netlify
.env.example                     образец секретов для сервера
```

Авторизованные учётные записи и материалы лучше запускать после тестирования на отдельном staging-домене.
